## Описание заданий

### Задание 1: Глобальная vs Разделяемая память

**Файл:** `task1_global_vs_shared.cu`

**Цель:** Сравнить производительность использования глобальной и разделяемой памяти.

**Что делает программа:**
- Умножает каждый элемент массива (1 млн элементов) на число
- Версия 1: Использует только глобальную память
- Версия 2: Загружает данные в shared memory перед обработкой
- Сравнивает время выполнения

**Ожидаемый результат:** Разделяемая память показывает ускорение для задач с переиспользованием данных.

### Задание 2: Влияние размера блока

**Файл:** `task2_block_size.cu`

**Цель:** Исследовать как размер блока влияет на производительность.

**Что делает программа:**
- Складывает два массива: C[i] = A[i] + B[i]
- Тестирует разные размеры блоков: 32, 64, 128, 256, 512, 1024
- Измеряет время для каждой конфигурации
- Определяет оптимальный размер блока

**Ожидаемый результат:** Оптимальный размер обычно 128-256 потоков.

### Задание 3: Коалесцированный доступ к памяти

**Файл:** `task3_coalesced_access.cu`

**Цель:** Продемонстрировать важность коалесцированного доступа к памяти.

**Что делает программа:**
- Копирует массив (1 млн элементов) двумя способами
- Версия 1: Коалесцированный доступ (соседние потоки → соседние адреса)
- Версия 2: Некоалесцированный доступ (stride паттерн)
- Сравнивает производительность

**Ожидаемый результат:** Некоалесцированный доступ в 10-30 раз медленнее!

### Задание 4: Оптимизация конфигурации

**Файл:** `task4_optimization.cu`

**Цель:** Подобрать оптимальные параметры сетки и блоков.

**Что делает программа:**
- Сложение векторов (10 млн элементов)
- Тестирует разные конфигурации блоков
- Сравнивает обычную и оптимизированную версию (loop unrolling)
- Выдает рекомендации по настройке

**Ожидаемый результат:** Оптимальная конфигурация зависит от GPU, но обычно 256 потоков.
