## Выполненные задания

### ✅ Задание 1 - Вычисление суммы массива на GPU
**Файл:** [task1_array_sum.cu](task1_array_sum.cu) (15KB)

**Что реализовано:**
- Последовательная сумма на CPU (простой цикл)
- Параллельная сумма на GPU с двухуровневой редукцией
  - Этап 1: Каждый блок суммирует свою часть
  - Этап 2: Финальное суммирование результатов блоков
- Использование `atomicAdd` для безопасного сложения
- Размер массива: 100,000 элементов

**Ключевые концепции:**
- Reduction (редукция) на GPU
- Атомарные операции
- Двухуровневая агрегация
- Когда GPU может быть медленнее CPU (маленькие данные)

**Комментарии объясняют:**
- Почему нельзя просто сложить все элементы в одном ядре
- Как работает двухуровневая редукция
- Что такое atomicAdd и когда его использовать
- Накладные расходы GPU для маленьких задач

### ✅ Задание 2 - Префиксная сумма (Scan) с shared memory
**Файл:** [task2_prefix_sum.cu](task2_prefix_sum.cu) (17KB)

**Что реализовано:**
- Последовательный prefix sum на CPU
- Параллельный prefix sum на GPU с использованием shared memory
  - Scan внутри каждого блока (используя shared memory)
  - Scan сумм блоков
  - Добавление offset к каждому блоку
- Размер массива: 1,000,000 элементов

**Ключевые концепции:**
- Prefix sum (scan) - что это и зачем нужно
- Shared memory для быстрого доступа
- Многоуровневый алгоритм scan
- Синхронизация потоков (`__syncthreads`)

**Комментарии объясняют:**
- Что такое prefix sum на примерах
- Алгоритм Blelloch scan (up-sweep / down-sweep)
- Почему нужна shared memory
- Как работает многоуровневый scan
- Применения prefix sum в реальных задачах

### ✅ Задание 3 - Гибридная программа CPU+GPU
**Файл:** [task3_hybrid.cu](task3_hybrid.cu) (17KB)

**Что реализовано:**
- Операция: возведение каждого элемента в квадрат
- Вариант 1: Весь массив на CPU с OpenMP
- Вариант 2: Весь массив на GPU
- Вариант 3: ГИБРИДНЫЙ - половина на CPU, половина на GPU ОДНОВРЕМЕННО
  - Использование CUDA streams для асинхронности
  - CPU обрабатывает первую половину с OpenMP
  - GPU обрабатывает вторую половину параллельно
  - Асинхронное копирование данных
- Размер массива: 10,000,000 элементов

**Ключевые концепции:**
- CUDA streams для асинхронного выполнения
- `cudaMemcpyAsync` для неблокирующей передачи
- Pinned memory для быстрого копирования
- OpenMP для параллелизма на CPU
- Перекрытие вычислений и передачи данных

**Комментарии объясняют:**
- Когда гибридный подход эффективен
- Как работают CUDA streams
- Как CPU и GPU могут работать одновременно
- Почему это может быть быстрее чем только GPU
- Накладные расходы и когда они доминируют

- Scatter/Scatterv для распределения данных
- Reduce для агрегации результатов
- Barrier для синхронизации
- Масштабируемость и накладные расходы

**Комментарии объясняют:**
- Что такое MPI и зачем он нужен
- Как работает каждая MPI функция
- Что такое rank и коммуникатор
- Как данные распределяются и собираются
- Почему ускорение не линейное
- Когда MPI эффективен

## Особенности реализации

### CUDA программы (Task 1-3):

**Макрос CUDA_CHECK:**
- Проверка ошибок после каждого вызова CUDA
- Вывод понятных сообщений об ошибках
- Номер строки где произошла ошибка

**Измерение времени:**
- `cudaEvent` для точного измерения GPU времени
- `omp_get_wtime()` для CPU времени
- Множественные прогоны для точности

**Проверка корректности:**
- Сравнение CPU и GPU результатов
- Проверка граничных случаев
- Вывод первых элементов для проверки

### MPI программа (Task 4):

**Подробный вывод:**
- Каждый процесс сообщает что делает
- Показывается распределение данных
- Время на каждом процессе
- Общая статистика

**Обработка неравномерных данных:**
- Использование Scatterv (не просто Scatter)
- Последний процесс может получить больше
- Корректная обработка остатка
